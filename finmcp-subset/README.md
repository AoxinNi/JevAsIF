# FinMCP-Bench 筛选子集（Jev-as-IF 用）

从 FinMCP-Bench 里筛出适合"基于图的工具编译"的任务：有工具调用链、能一次规划完成、能用回放环境评测。这是后续建图（SOG）和全部实验的数据来源。

重新生成：`python finmcp-subset/filter.py`（依赖 `../Notebook/jif`，几秒钟；结果是确定的）。

## 筛选规则

### 单元

- 多工具子集：一个任务一个单元。
- 多轮子集：一轮对话一个单元。之前的消息（包括之前几轮的工具返回）视为已知上下文。
- 单工具子集：全部排除，因为只有一次调用、没有调用链。

### 分组

| 组 | 条件 | 在实验里的用途 |
| --- | --- | --- |
| **D** 含语义判断 | 至少一处参数是"从上游多个候选里选一个或选一部分" | 主实验：Jev-as-IF 的主场 |
| **M** 只有机械依赖 | 有上下游依赖，但都是直接引用或全选 | 对照：没有语义判断时也不能变差 |
| **I** 无依赖 | 两次以上调用，彼此独立 | 参考：LLMCompiler 和 PTC 本来就能处理（只保留多工具子集的） |

判断"从候选中选"时，日期、小数、分页参数，以及用户原话或已知上下文里出现过的值都不算。

### 排除

- 调用少于 2 次；
- 含需要生成内容的调用（`RenderHtmlToPdf`、`RenderEchart`：要把回答渲染成 HTML 或图表）；
- 多轮子集里无依赖的轮次：这些轮次的多次调用大多是报错后改参数重试，或者复用前几轮已经拿到的值，没有可编译的调用链。

**标记（不排除）**：参考轨迹含报错或非 JSON 返回；不涉及用户身份（没有 userId）。

**切分**：按"来源 × 组"分层，20% 开发集 / 80% 测试集，随机种子 2026。同一段多轮对话的各轮在同一侧，避免泄漏。开发集用于调提示词、先导实验和门控标定；测试集只在最后报告时使用。

- 共 203 道，其中选一个 87 道、选一部分 116 道；

- 候选数中位数 8，90 分位 20，最多 40，全部不超过 Jev 的 255 个选项上限。

**建议**：主实验用多工具子集。多轮子集几乎都是 M 组，D 组只有 7 轮，适合作补充，不适合单独下结论。

### `tasks.jsonl` 的字段

| 字段 | 含义 |
| --- | --- |
| `id` | 多工具 `multi_tool:30`；多轮 `multi_turn:76#t3`（第 3 轮） |
| `source`、`unit` | 来源子集；`task` 或 `turn` |
| `dialogue_id`、`turn` | 多轮单元所属的对话和轮次 |
| `group`、`group_name`、`split` | 分组（D/M/I）；开发集或测试集 |
| `question` | 本单元的用户请求 |
| `user_id` | 用户 id（运行时注入）；没有则为 null |
| `history` | 多轮单元之前的全部消息（多工具单元为空） |
| `messages` | 本单元的参考轨迹（原始格式） |
| `reference_answer` | 参考回答（本单元最后一条助手消息） |
| `scenery`、`difficulty` | 原数据集的场景和难度 |
| `tools`、`n_calls`、`n_steps`、`has_parallel` | 调用的工具序列、调用次数、步数、是否有并行调用 |
| `flags` | 标记 |
| `screen` | 各类依赖的计数：pick_one / pick_subset / pick_all / reference |
| `decisions` | 判断步骤摘要：来源字段 → 目标参数、候选数、选中的值 |

## 人工核实：审核工具

```bash
python finmcp-subset/review_app.py          # 浏览器会自动打开 http://127.0.0.1:8777
```

只用 Python 标准库，数据不离开本机。页面每次显示一条 D 组单元：

- **问题与基本信息**：场景、难度、工具链长度（调用次数、步数、是否并行）、标记；
- **待判断的步骤**：从哪个工具的返回里、在几个候选中选了哪几个、传给了谁；候选逐条列出，选中的行高亮；
- **工具链路拓扑**：从上到下是调用步骤，橙色线是语义判断，灰色线是机械依赖，跨越多步的依赖从右侧绕行，节点里的蓝字是来自客户原话的参数；悬停看详情，点节点跳到调用明细；
- **调用明细**：每个工具的中文功能说明（根据工具名、参数和返回推断）、每个参数的来源（上游第几次调用 / 客户原话 / 常量 / 运行时注入的身份）、返回结果（点开查看）；
- **参考回答**，多轮单元还有之前的对话。

右侧回答两个问题，可以加常见情况的标签和备注。**每次修改都会自动保存**到 `review_labels.json`，并同步到 `review.csv` 的最后三列。重跑 `filter.py` 也不会覆盖已做的判断。

快捷键：`1 2 3` 回答问题 1，`Q W E R` 回答问题 2，`← →` 翻页，`Enter` 跳到下一条未完成。默认开发集排在前面；顶部可以只看未完成的条目，或只看开发集。

已知局限：同一步里有很多并行调用的少数单元（约 15 条），拓扑图会比较密，这时以下方的调用明细为准。

## 注意

- **人工核实还没做**。117 个 D 组单元需要用上面的审核工具过一遍，确认确实需要语义判断、标准答案合理。可以先做开发集的 24 条。
- **标准答案带有随意性**。多工具和多轮的参考轨迹由 Qwen3-235B 生成，有些"选一个"只是多个合理答案之一，见 `review.csv` 最后两列。
- **统计口径**：这里的 D 组数量以本脚本为准（多工具 110 条，占 44%），取代 `../finmcp-analysis/` 里较早的 149 条（60%）。
