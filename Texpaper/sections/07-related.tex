\section{Related Work}
\label{sec:related}

\paragraph{Code as action.} CodeAct~\cite{wang2024codeact} and programmatic tool calling~\cite{anthropic2025advancedtooluse} let the model chain calls in code and keep intermediate results out of the context. AppWorld~\cite{trivedi2024appworld} is a demanding testbed for this style. These agents write code against raw tool schemas, nothing checks the code before it runs, and a semantic judgment mid-program sends control back to the model. \jif keeps the medium but adds a graph-derived type system, static checking, and in-program System-1 primitives.

\paragraph{Plan-then-execute compilers.} ReWOO decouples planning from observation with evidence variables~\cite{xu2023rewoo}. LLMCompiler executes a task DAG in parallel and re-plans when needed~\cite{kim2024llmcompiler}. Related lines fuse similar calls~\cite{singh2024llmtoolcompiler}, plan with abstract placeholders that tools later fill~\cite{gao2024coa}, plan backwards from the target API~\cite{zhang2024reversechain}, or train small planners~\cite{erdogan2024tinyagent}. These methods resolve mechanical dependencies at execution time and call the LLM back for everything else. DSPy compiles declarative pipelines of language-model calls~\cite{khattab2024dspy}, which optimizes prompts rather than tool chains.

\paragraph{Graph-guided tool use.} Parameter-level API dependency graphs nearly double multi-tool performance, but they are annotated by experts or inferred by models~\cite{lee2026innout}. TaskBench represents decomposed tasks as tool graphs~\cite{shen2024taskbench}. Graph-based planners prune a tool dependency graph before planning~\cite{navi2025} or learn to emit dependency-aware subtask graphs~\cite{gap2025}. Dataflow synthesis treats dialogue state as an executable graph~\cite{andreas2020dataflow}. Dynamic ontologies have been proposed as an agent kernel for knowledge and reasoning~\cite{zhang2026oak}. These works use a single graph to select or plan tools. \jif uses a split graph to \emph{compile}: the operation side types and checks the program, and the object side gives run-time decisions their semantics.

\paragraph{Systems for LLM applications.} Parrot exposes application DAGs to the serving layer~\cite{lin2024parrot}. Asynchronous function calling overlaps generation with execution~\cite{gim2024asynclm}. These systems shorten the time spent waiting for the LLM. \jif removes the LLM from the execution loop except where the gate calls it back.

\paragraph{System-1 judgments, calibration and cascades.} LLM cascades escalate from cheap to expensive models~\cite{chen2023frugalgpt}, and System-1 judges with escalation have been evaluated in~\cite{li2026jevjudge}. Conformal prediction gives distribution-free coverage~\cite{vovk2005algorithmic,angelopoulos2021gentle}, and conformal risk control extends it to general losses~\cite{angelopoulos2024crc}. KnowNo asks for help when the prediction set is not a singleton~\cite{ren2023knowno}. Selective classification trades coverage for risk~\cite{geifman2017selective}. Agents also bind the wrong entity even with the right tool, and confidence-gated binding is one remedy~\cite{suresh2026entity}. \jif applies these ideas to the conditionals of a compiled program.

\paragraph{Benchmarks.} Nested and multi-hop tool benchmarks~\cite{basu2024nestful,ye2025toolhop,patil2025bfcl,zhong2025complexfuncbench,maekawa2026funcbenchgen,song2023restgpt} and financial MCP benchmarks~\cite{zhu2026finmcp} measure tool-use competence. We additionally screen tasks by whether they contain semantic decisions, because that is where compilation methods differ.
